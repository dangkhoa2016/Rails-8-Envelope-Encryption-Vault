# Ruby Envelope Vault 0.1.4 Release Notes

Release date: 2026-09-30

## Highlights

0.1.4 adds production-gated AWS KMS support for envelope-key wrapping while preserving the existing local-file provider.

The release was promoted only after live AWS KMS acceptance with two customer-managed keys, service-level key rotation, historical decrypt verification, full regression tests, and static/security checks.

## AWS KMS provider

- Adds AWS KMS client integration.
- Adds external KMS envelope-key provider.
- Uses encryption context bound to user, vault item, vault item version, and purpose.
- Keeps DEKs opaque outside KMS wrapping operations.
- Maps provider failures to generic application errors without leaking credential details.
## Registry integration

`KeyProviders::Registry` supports:

- `local_file`
- `aws_kms`

AWS KMS activation is explicit and fail-closed:

- `VAULT_KEY_PROVIDER=aws_kms`
- `VAULT_ACTIVE_KEK_ID` must be configured
- AWS region must be configured
- unknown providers still fail closed
- no implicit fallback to local-file keys

## Live rotation acceptance

Live acceptance verified key rotation from KMS key 01 to key 02:

- payload ciphertext remained unchanged
- wrapped DEK changed
- KEK id moved to key 02
- reveal after rotation succeeded
- historical wrapped DEK remained decryptable with key 01
- old key registry state became `decrypt_only`
- new key registry state became `active`
