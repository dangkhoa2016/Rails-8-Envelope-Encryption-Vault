# Ruby Envelope Vault 0.1.5 — Stable Release Notes

Status: sealed, promoted, post-promotion verified, and off-host round-trip verified.
Base: sealed stable 0.1.4.

## Summary

0.1.5 focuses on portability, recoverability, and production-facing usability. It does not introduce a database migration or change the envelope-encryption/key-provider persistence contracts.

## Portability and recovery

- portable `activate-runtime.sh` for Kaggle, Google Colab and generic XDG/HOME Linux hosts;
- `activate-kaggle.sh` retained as a compatibility wrapper;
- Ubuntu 24.04 ALSA dependency selection using `libasound2t64` with `libasound2` fallback;
- new-host restore no longer depends on `/mnt/workspace` or mandatory tmux;
- PostgreSQL and Redis collision recovery is runtime-proven;
- PostgreSQL socket provisioning follows the dynamically selected port;
- migration bundle secrets location is explicit/portable and no longer embeds a Colab-specific private DR path.

## Product UX

- all seven Vault templates now explain intended use and typical fields;
- create/edit forms have clearer information architecture;
- edit/versioning semantics are explained before save;
- item detail pages explain template structure and lifecycle actions;
- search/filter controls have accessible labels and visible reset state;
- fixed stale filter UI caused by Turbo Stream handling of the privacy-preserving POST search form.

## Security workspace UX

- Dashboard shows real MFA and active-session posture;
- Password, MFA and Sessions share a consistent security-settings navigation;
- Audit empty states distinguish no history from no filtered matches;
- Sessions has a defensive no-records state.

## Compatibility boundary

Unchanged from 0.1.4:
- `db/` schema and migrations;
- `Gemfile` and `Gemfile.lock`;
- routes;
- Vault crypto services;
- key-provider services;
- `VaultItemVersion` persistence behavior;
- `MfaSetting` persistence behavior.
