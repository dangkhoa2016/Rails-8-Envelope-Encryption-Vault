# Ruby Envelope Vault 0.1.3-RC1

## Purpose

0.1.3-RC1 consolidates the accepted 0.1.2-FIX46 baseline into a milestone release candidate. It does not introduce a new database migration or change the envelope-encryption data model.

## Consolidated production evidence

The candidate carries forward and re-runs the accepted release gates for:

- encrypted vault and MFA secret handling,
- backup, restore, off-host and new-host recovery,
- automated UX/accessibility checks with manual accessibility still explicitly pending,
- HTTP security headers and cookie policy,
- branded production error handling and request correlation,
- logging redaction,
- CSRF origin validation,
- abuse resistance and rate limiting,
- production session lifecycle,
- sealed-source integrity and explicit promotion.

## Upgrade contract

0.1.3-RC1 adds a FIX46 upgrade preflight that proves:

- the migration file set is identical to FIX46,
- running production `db:migrate` is idempotent,
- no pending migrations remain,
- the existing persistent production database is reused,
- project-doctor passes from the candidate source,
- upgrade evidence contains no secret values.

## Documentation cleanup

The README release marker is updated from the stale FIX32 label to the 0.1.3 release-candidate / FIX46 accepted-baseline model.

## Release boundary

This is a release candidate. The live accepted release must remain FIX46 until the candidate passes full verification, pre-promotion sealing, explicit promotion, post-promotion evidence and off-host round-trip acceptance.
