# Production Security Checklist — 1.0.0
Before storing real secrets on an Internet-facing deployment, require every item below to pass.
> 🌐 Language / Ngôn ngữ: **English** | [Tiếng Việt](PRODUCTION-CHECKLIST.vi.md)

- [ ] Ruby 3.4.11 active and `bundle install` succeeds with `Gemfile.lock` frozen.
- [ ] `bin/rails db:prepare` succeeds against PostgreSQL 17.
- [ ] `bin/rails test`, `script/crypto-self-test`, and `script/security-self-test` pass.
- [ ] `script/ops-check` passes with the deployment environment loaded.
- [ ] For the final deployment gate, `OPS_REQUIRE_BACKUP_CONFIG=1 OPS_REQUIRE_HTTPS_SMOKE=1 script/ops-check` passes.
- [ ] Brakeman and bundler-audit pass.
- [ ] Production Docker image cold-build passes.
- [ ] `APP_HOSTS` contains only intended hosts.
- [ ] `FORCE_SSL=true` and `script/production-smoke` passes through the real HTTPS endpoint.
- [ ] `ALLOW_SIGNUPS=false` and `DEMO_MODE=false` for the personal vault.
- [ ] `REQUIRE_MFA=true` and `REAUTH_ON_REVEAL=true`; owner has enrolled TOTP and stored recovery codes offline.
- [ ] Vault KEK file is exactly 32 bytes, mode 0600/0400, outside Git and PostgreSQL.
- [ ] The runtime container UID/GID (1000 by default) can traverse the KEK directory and read the key, without widening group/world permissions.
- [ ] A second offline recovery copy exists for every KEK still needed to decrypt backups.
- [ ] `bin/rails vault:keys:verify` passes.
- [ ] A fake canary secret is created and `script/prove-no-plaintext` passes.
- [ ] Key rotation dry-run and a real rewrap test pass before retiring an old KEK.
- [ ] Offsite PostgreSQL backup is `age`-encrypted (or a plaintext backup has been explicitly accepted and separately protected); checksum verifies.
- [ ] `script/dr-rehearsal` verifies an encrypted backup, restores into a guarded fresh database, decrypts an exact known fake canary value, and cleans up the rehearsal database.
- [ ] `script/ops-report` is consumed by monitoring/CI without publishing its diagnostics through `/ready`.
- [ ] Scheduled backup jobs use `script/ops-maintenance` (or equivalent) and persist/ship the safe report separately from credentials.
- [ ] `script/backup-retention` is reviewed in dry-run mode before `RETENTION_APPLY=1`; retained backup count is never configured below 2.
- [ ] Backup alerting treats checksum, decrypt, canary, database-create, and rehearsal cleanup failures as fatal.
- [ ] Session idle/absolute expiry, session-ID rotation after reauthentication/password/MFA changes, and reauthentication behavior are manually smoke-tested.
- [ ] Public demo deployment, if any, is physically/logically separate and contains fake data only.

A database backup is not considered recoverable until restore + decrypt succeeds.

## acceptance gate

For a deployment candidate, run:

```bash
REQUIRE_REAL_HTTPS=1 \
REQUIRE_KEK_RECOVERY=1 \
REQUIRE_BACKUP_ACCEPTANCE=1 \
REQUIRE_REAL_OFFSITE=1 \
APP_URL=https://actual-host.example \
RECOVERY_KEK_DIR=/independent/recovery/keks \
ACCEPTANCE_BACKUP_FILE=/secure/backups/ruby-envelope-vault-....dump.age \
OFFSITE_DRIVER=rclone \
OFFSITE_RCLONE_DEST='remote:vault-backups' \
script/production-acceptance
```

Do not mark this strict gate PASS from the Kaggle filesystem adapter or a same-host KEK copy.

## external HTTPS notes

Cloudflare Quick Tunnel can be used to prove the application responds correctly through a real external TLS terminator, but it is not accepted as the final production host.

Strict offsite acceptance additionally requires:

- `OFFSITE_DRIVER=rclone`;
- a named configured rclone remote;
- a backend type other than `local`, `memory`, or `alias`;
- successful encrypted-backup upload;
- successful retrieval;
- exact SHA-256 match after retrieval.

A missing or unsuitable remote must keep `script/production-acceptance` non-zero.

## offsite recovery proof

- [ ] A backup downloaded from the real rclone remote passes `script/verify-backup` in a fresh staging directory.
- [ ] `script/offsite-dr-rehearsal` restores that downloaded artifact into a fresh guarded database and matches the exact fake canary.
- [ ] The rehearsal database and staging directory are removed after PASS.
- [ ] Checksum sidecars generated by current backups contain only the backup basename, not an absolute source path.

## scheduled operations

- [ ] A persistent host scheduler (systemd timer, cron, or equivalent) invokes `script/scheduled-ops daily`.
- [ ] A periodic scheduler invokes `script/scheduled-ops dr` at the chosen recovery-test cadence.
- [ ] `OPS_STATE_DIR`, `OPS_EVIDENCE_DIR`, and any alert log directory are persistent and mode-restricted.
- [ ] Alert delivery is tested with an intentional safe failure before relying on it.
- [ ] Overlapping invocations are verified to exit 75 due to the runner lock.
- [ ] Scheduler environment/secret file is outside Git and readable only by the operator/service account.

## persistent scheduler host

- [ ] Dedicated scheduler service user/group exists.
- [ ] `/etc/ruby-envelope-vault/ops.env` is configured with no placeholders and mode 0600.
- [ ] `DATABASE_URL`, production Rails/KEK context, age recipient/identity, `RCLONE_CONFIG`, offsite destination and fake DR canary are all configured.
- [ ] Service account can read the recovery age identity, active Vault KEK and rclone config.
- [ ] Service account can write backup, state and evidence directories; directories are 0700/0750.
- [ ] `script/ops-scheduler-doctor systemd` (or `cron`) passes on the real host.
- [ ] Timers/jobs are enabled only after doctor PASS and a manual `script/scheduled-ops daily` plus `dr` run succeeds.
